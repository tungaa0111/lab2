## 2. Туршилтын тухай

## 4. Stages тест

Stages тестээр хэрэглэгчийн тоог эхлээд 5, дараа нь 30, 100 болгож нэмэгдүүлээд эцэст нь 0 болгож бууруулсан.

- Дундаж хугацаа: 350.02 ms
- p95: 589.11 ms
- Хүсэлтийн хурд: 34.996 req/s
- Алдааны хувь: 0%

Тестийн явцад хэрэглэгчийн тоо өөрчлөгдөхөд системийн хариу өгөх хугацааг ажигласан.

## 5. SLO болон Threshold тест

SLO тохируулахдаа p95 хариу өгөх хугацааг 1000 ms-ээс бага, алдааны хувийг 1%-ээс бага байхаар сонгосон. Baseline тестийн p95 нь 373.30 ms байсан. Үүнээс өндөр босго сонгож, тестийн үед хариу өгөх хугацаа өөрчлөгдөх боломжийг тооцсон.

**PASS тест:**
- p95 босго: 1000 ms
- Бодит p95: 430.28 ms
- Алдааны хувь: 0%
- Үр дүн: PASS

**FAIL тест:**
- p95 босго: 1 ms
- Бодит p95: 2.48 s
- Алдааны хувь: 0%
- Үр дүн: FAIL

FAIL тестэд босгыг зориуд маш бага тавьж, threshold шаардлага хангахгүй үед k6 хэрхэн мэдээлдэгийг шалгасан.

## 6. Дүгнэлт

Энэ лабораторийн ажлаар k6 ашиглан веб сайтын ачааллыг шалгаж үзлээ. 5, 30, 100 хэрэглэгчтэй үед тус тус тест ажиллуулж үр дүнг харьцуулсан. Хэрэглэгчийн тоо нэмэгдэхэд нийт хүсэлт болон хүсэлтийн хурд нэмэгдсэн. Харин энэ туршилтаар p95 хугацаа нэмэгдээгүй, харин бага гарсан. Бүх гурван үндсэн тестийн алдааны хувь 0% байсан. Мөн stages ашиглан хэрэглэгчийн тоог үе шаттай өөрчилж туршсан. Threshold тохируулж нэг тестийг PASS, нөгөөг нь FAIL болгож шалгасан. Ингэснээр k6 дээр босго тохируулах, үр дүнг унших талаар ойлголт авсан. Энэ үр дүн нь зөвхөн тухайн тест хийсэн үеийн нөхцөлийг харуулж байгаа.
